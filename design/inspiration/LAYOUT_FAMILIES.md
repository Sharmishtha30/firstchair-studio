# Layout families and selection guide

This guide organises all 98 static placements in GOLDEN_SET.md into 13 primary layout families. A reference has one primary family for retrieval; its headline style, visual treatment and writing approach can be reused across families. There are two identified apparent duplicate placements and one explicitly linked layout variant. Other overlaps are possible; 96 remaining placements are not a claim of 96 unique designs.

This is a reference and implementation guide. It has not been wired into the running application. The accompanying LAYOUT_INDEX.json provides the same classification in a structured file the builder can read. All 98 records point to available archived screenshot boards. Board images include several creatives; the record's item number identifies the relevant example in the original set.

## Choose from the website, then choose a layout

1. Extract the brand's actual colours, font families, logo, imagery, product/service description, offer, destination and supporting facts. Keep the source URL beside each factual claim. Mark missing information as missing; mark audience and tone interpretations as inferences.
2. Write a short creative brief: the likely audience, one concrete situation they face, the relevant offer, one supported takeaway and one action. Do not default every site to a wellness product or manufacture a pain point.
3. Check available evidence and assets before selecting a family. Reviews unlock proof formats; real variants unlock grids; a documented process unlocks a sequence. Missing inputs trigger the stated fallback.
4. Rank eligible families by how clearly they express the brief, how well the available imagery fits, and whether their text can be read on a phone. These are editorial criteria, not predicted conversion scores.
5. For multiple outputs, choose different information structures where useful. Changing a background colour or putting the same copy inside another social interface does not create a meaningfully different concept.
6. Write the content before fitting the final composition. Preserve the brand's identity while adapting the layout. Reflow or shorten content rather than shrinking it until unreadable.
7. Check the rendered creative and the actual exported file. Correct clipped text, weak contrast, distorted products, missing characters, incorrect reading order and unsupported assertions before calling it ready.

## The 13 families

### Image and headline — 14 placements

Choose when: A strong product, person, setting or outcome-related image is available.

Composition: One dominant image; short headline in a clear area; one supporting line; quiet brand mark and action.

Writing: Name a recognisable situation or desire, then explain the product connection.

Required material: A relevant image and supported product proposition.

Fallback: Use a typography-led explanation when suitable photography is absent.

Across website types: A software screenshot with a specific workflow frustration; a service scene with a relevant customer question.

## Keep writing angles separate from layout families

Use a specific situation, an unanswered question, a price objection, a supported contrast, a process, a real customer observation or an actual announcement as the writing angle. A “turns out” headline, an age callout and a “three reasons” hook are angles; none automatically needs a new template. Choose language that fits the website's audience rather than inheriting the source ad's tone.

For each draft, ask: could this headline fit any competitor unchanged? If yes, add a real product detail or a more specific audience situation. Does the body explain the headline? Does the action follow naturally from the value? Replace unsupported superlatives with concrete details. Do not force a long explanation into a static: simplify the idea or expand it into a carousel.

## Adapt the family to a carousel

Keep the two AevyTV carousel references in Sets 001 and 003 as separate visual directions: editorial typography/collage and image-led editorial. They are partial reference sets, not validated universal carousel templates.

For a new carousel, give each slide one job: open with a relevant question or tension, develop a small number of supported points, then offer a natural next action. The exact slide count follows the material. A sequence can become one step per slide; a comparison can become one criterion per slide; a checklist can become one reason per slide. Keep typography, palette and repeated elements consistent while varying composition. Every slide must add information.

## Builder handoff and acceptance checks

Use LAYOUT_INDEX.json to retrieve references by family; use GOLDEN_SET.md for detailed observations and limits. The JSON is a reference catalogue, not a functioning renderer or a model integration. Store the selected family, reference IDs, source facts, audience inference, asset choices and reason for selection with each creative plan. Keep this implementation detail out of the customer-facing creative.

Check selection on contrasting inputs: a software site with no customer quotes, a service business with real reviews, a shop with several variants, an education site with a documented curriculum, and a sparse homepage with little imagery. Expected behaviour: relevant families selected from available facts, brand identity retained, honest fallbacks used, and no invented discounts, reviews, medical outcomes or community endorsement. These cases are proposed checks; they have not been run against the application.

Completion for implementation means the exported Instagram and LinkedIn assets have been opened and visually checked, including a phone-sized preview. This organisation task only validates catalogue coverage, family assignment, duplicate links and archived image availability; it does not establish generated creative quality.

## Learning loop roadmap — proposed, not implemented

The reference library now has a generated counterpart in the app's `convex/referenceLibrary.ts`. Its written guidance is passed to planning, drafting, repair and review. It adapts families to the existing five renderer layouts; it does not supply reference images as model inputs or implement every observed visual treatment. `scripts/sync-reference-library.py` refreshes this counterpart from a reviewed catalogue. New references must be reviewed and synchronised before the running app uses them.

Recommended learning unit: one website brief, candidate creative, selected family/reference IDs, catalogue version, model version, rendered export, human feedback and revision. Store these in Convex when implemented. Keep copy, visual quality, brand fit and factual accuracy as separate ratings. Ask for a reason such as generic hook, too much text, poor image choice or wrong audience. Approval means preferred, not proven to convert.

Loop: collect candidate references → remove duplicates → classify and review → add accepted patterns → generate → compare alternatives → record human preference → test changed selection rules against a fixed set of varied websites → promote only when quality improves without breaking evidence or readability checks. Keep rejected versions and rollback information. No model retraining or local GPU is needed for this approach; generation still consumes the connected account's allowance.

Internet discovery should target gaps (for example B2B software comparisons or service-business proof), not indiscriminately collect more wellness ads. Start with supplied boards and accessible public pages. Record source URL, creator, access date, usage constraints and what is worth borrowing. Use authorised integrations where needed; do not assume a Pinterest or Canva URL makes its whole library accessible or reusable. Imported content remains untrusted reference material. Keep discovery candidates separate from the approved collection.

Actual post results can be added later with user-supplied or authorised analytics: impressions, saves, qualified clicks and conversions, plus platform, audience, date and campaign context. Do not treat likes as design quality or compare raw conversion totals across unequal audiences. Prefer repeated controlled comparisons before changing defaults. No scheduled crawler, account integration, automatic promotion, analytics collection or feedback database has been enabled by this documentation.
